# Netlify Database 永久浏览量计数设计

日期：2026-09-06
状态：设计已获用户口头批准并完成规格自检，待用户最终复核

## 1. 目标

为“社会学实验室”Hugo 网站增加所有访客共享、跨设备且永久累计的页面浏览量。网站继续由 Netlify 构建和托管，浏览量由 Netlify Function 写入 Netlify Database。计数故障不得阻止正文、图片、代码块和音乐播放器正常加载。

需要覆盖：

- 简介页；
- “SPSS软件应用”分类下的全部现有及新增文章；
- 其余全部现有及新增文章。

只在访客打开简介页或单篇文章页时增加对应页面浏览量。首页、分类页、归档页和分页列表展示文章摘要时，不增加这些文章的浏览量。

## 2. 明确的计数规则

每次完整加载目标页面，包括人工刷新，浏览量增加 1。当前需求不区分访客、不去重，也不排除普通搜索引擎或自动化浏览。

页面第一次写入数据库时按以下规则建立基数：

| 页面类型 | 初始基数 | 第一次成功访问后的显示值 |
|---|---:|---:|
| 简介页 | 1362 | 1363 |
| SPSS文章 | 2001～2600之间随机整数 | 随机基数 + 1 |
| 其他文章 | 1300～1600之间随机整数 | 随机基数 + 1 |

随机基数仅在该页面第一次写入时生成，随后固定保存。数据库中的当前值是唯一事实来源，浏览器不得自行叠加或缓存浏览量。

## 3. 方案选择

采用 `@netlify/database` 直接 SQL：

- 数据模型只有一张表，直接 SQL 比 Drizzle ORM 更少依赖、更少生成文件；
- 使用 PostgreSQL `INSERT ... ON CONFLICT ... DO UPDATE` 原子完成首次初始化或加 1；
- 数据库连接由 Netlify 运行环境提供，连接字符串不进入仓库或浏览器。

不采用以下方案：

- 不蒜子：无法可靠控制指定初始值和数据归属；
- 浏览器 `localStorage`：只能在单个设备本地累计，不能共享；
- GitHub Pages 单独计数：静态托管不提供请求时数据库；
- Drizzle ORM：对单表计数增加无必要的结构和迁移复杂度。

## 4. 组件与职责

### 4.1 数据库迁移

在 `netlify/database/migrations/` 中建立 `page_views` 表，字段至少包括：

- `page_key`：规范化后的页面唯一键，主键；
- `page_type`：`about`、`spss` 或 `post`；
- `initial_count`：首次生成的基数；
- `view_count`：当前累计值；
- `created_at`：首次创建时间；
- `updated_at`：最近递增时间。

迁移必须可重复部署，不能删除或重置已有生产数据。

### 4.2 Netlify Function

建立同源接口 `/api/page-view`，仅接受 `POST`。请求包含页面键和页面类型；Function 必须：

1. 校验请求体格式、字符串长度和允许的页面类型；
2. 将页面键规范化，忽略查询参数和锚点，并统一尾部斜杠；
3. 根据页面类型确定固定或随机基数，不能相信客户端提交的数值；
4. 使用单条原子 UPSERT 完成首次插入或 `view_count + 1`；
5. 返回 JSON：规范化页面键和最新浏览量；
6. 对不支持的方法返回 405，对无效输入返回 400，对数据库异常返回 503；
7. 不在响应或日志中暴露数据库连接信息。

接口与网页保持同源，不开放宽泛 CORS。客户端不能直接连接数据库。

### 4.3 Hugo 页面标记

以站点本地 override 覆盖浏览量模板，不修改 `themes/hugo-theme-next` 子模块。目标页面输出：

- 规范化页面键；
- 页面类型；
- 加载占位状态；
- 用于无障碍读取的文字说明。

简介页归类为 `about`。SPSS文章依据 Hugo 分类信息判断为 `spss`，而不是依赖标题文字。其他单篇文章归类为 `post`。未来按相同分类发布的文章自动适用，不需要逐篇修改脚本。

### 4.4 浏览器脚本

新增一个站点脚本，在 DOM 就绪后：

1. 查找当前页面唯一的浏览量元素；
2. 发送一次 `POST /api/page-view`；
3. 成功时将返回值写入页面；
4. 失败或超时时显示“—”，不弹窗、不反复重试、不阻塞其他资源；
5. 防止同一页脚本被重复初始化，但人工刷新仍按需求增加 1。

前端不得预先显示虚假的基数。数据库响应到达前显示加载状态。

### 4.5 现有统计配置

停用文章浏览量所使用的不蒜子脚本，避免一次访问被两个系统同时统计或旧数值覆盖新数值。既有“网站资讯”卡片不恢复已经删除的总访客数和页面浏览量项目。

## 5. 数据流

```text
访客打开简介页或单篇文章页
  -> Hugo 输出页面键和页面类型
  -> page-view.js POST /api/page-view
  -> Netlify Function 校验输入
  -> PostgreSQL 原子初始化或递增
  -> Function 返回最新 view_count
  -> 浏览器更新页面显示
```

首页和各类列表页不调用计数接口，因此预览文章不会增加浏览量。

## 6. 页面键与持续性边界

默认使用规范化后的站内永久链接作为 `page_key`。同一 URL 在刷新、不同设备和不同访客之间共享一条记录。

边界：如果以后修改文章永久链接，数据库会把新 URL 视为新页面。需要保留旧计数时，应在改链接的同一次变更中执行数据库键迁移；本次不为尚未发生的改名增加额外映射系统。

## 7. 部署流程

仓库新增 `package.json` 与锁文件，安装 `@netlify/database`。沿用现有 `netlify.toml`：

- 构建命令继续使用 Hugo 0.154.5 Extended；
- 发布目录继续为 `public`；
- Functions 使用默认目录 `netlify/functions/`，或在配置中明确写出同一路径；
- 不把数据库连接字符串写入 `netlify.toml`。

推送 GitHub 后，Netlify 安装依赖、构建 Hugo、部署 Function、配置数据库并应用迁移。若自动配置未发生，则在 Netlify 控制台的 `Data & Storage > Database` 手工创建数据库后重新部署。

Deploy Preview 使用独立数据库分支；预览环境测试不得改变生产浏览量。生产验证必须只进行少量、可解释的真实访问。

## 8. 测试与验收

### 8.1 静态构建

- `hugo --gc --minify` 成功且无新增模板错误；
- 首页、分页、分类、归档、简介及抽样文章均能生成；
- 不再输出不蒜子页面计数脚本；
- 音乐播放器、Stata/SPSS代码高亮、搜索和图片路径不受影响。

### 8.2 Function 与数据库

- 简介空表首次请求返回 1363，第二次返回 1364；
- SPSS空表首次请求落在 2002～2601，第二次严格增加 1；
- 其他文章空表首次请求落在 1301～1601，第二次严格增加 1；
- 并发请求后最终值等于成功请求数之和；
- 无效类型、超长页面键、错误方法分别得到预期错误；
- 数据库故障时网页仍完整显示，浏览量位置显示“—”。

### 8.3 页面范围

- 打开首页、任一分页、分类页或归档页不会增加文章计数；
- 打开简介页增加简介计数；
- 打开单篇文章增加该文章计数；
- 刷新目标页面再次增加 1；
- 两台设备访问同一页面看到同一累计序列。

## 9. 运行成本与监控

该方案使用 Netlify Free 的统一 credits。Function 请求本身很少，主要不确定性来自数据库在低频、分散访问下的唤醒计算时间，以及音乐文件带宽和正式部署次数。

上线后第一个月应在 Netlify `Usage & billing` 中至少每周检查一次：

- Database compute；
- Function compute；
- Bandwidth；
- Production deploys；
- 剩余 credits。

Free credits 用尽会暂停同一团队下的全部项目。因此计数接口的简洁性可以降低消耗，但不能保证 300 credits 在所有访问分布下必然够用。

## 10. 不在本次范围内

- 独立访客 UV；
- 按天、月统计；
- 管理后台；
- 人工修改计数的公开接口；
- 过滤全部机器人或防刷计数；
- 将历史不蒜子数据迁入数据库；
- 自动购买 credits 或升级 Netlify 套餐。
